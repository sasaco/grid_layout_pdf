## 調査方法と範囲

- 全 10 ファイル・251 ページについて用紙寸法、フォント資源、文字サイズ、文字・等号座標、画像・描画オブジェクト、ページテキストを抽出した。
- 全ファイルから選んだ 14 ページを PNG に描画して目視確認した。目視対象は下表の「確認ページ」。251 ページ全部を目視したという意味ではない。
- 座標は PDF ページ左上を原点とする pt。本文の `origin.y` は文字基線、`bbox` は抽出エンジンが示す文字ボックスであり、実際の黒画素輪郭とは区別する。
- 抽出・描画は一時的な `uv run --no-project --with pymupdf` 環境を使用。Poppler は PATH と探索した Codex/local/WinGet ディレクトリには見つからず、MuPDF で代替描画した。これは開発用調査手段であり、製品依存の採用決定ではない。
- 詳細抽出結果は `tmp/pdfs/sample-reports/inventory.json`、ページテキストと確認用 PNG は同ディレクトリにある。一時資料に依存せず判断できる主要値を本書に残す。
- 参照 PDF の SHA-256 を採取し、終了時に同一であることを確認した。値は末尾に記す。

## GridLayout との関係で重要な測定

### 文字送りはフォントサイズと別の概念

`08_線路.pdf` p2 の本文「フーチングはすべて剛域とする」は MS-Mincho、抽出サイズ9.9398 ptである。基線 y=260.398 pt、文字開始 x は117.96、128.04、138.12、148.20…となり、全角の送りは **10.08 pt**。各文字ボックス幅は10.00 pt。

同じページの数値「12.150」は基線 y=181.918 pt、開始 x は435.36、440.40、445.44、450.48…で、半角の送りは **5.04 pt**。各文字ボックス幅は5.00 pt。

別途 A4 グリッド調査で報告された16.08 ptの列ピッチ、15.48 ptの行ピッチに対して、この本文の送り・行間がそのまま一致するわけではない。特に16.08/2=8.04 ptの枠に10 pt幅の全角文字を連続配置すると、文字ボックスが約1.96 pt重なる。参照計算書から「全角も半セルでよい」とは判断できない。

**提案:** `font_size`、文字の送り規則、ブロック開始位置のグリッド、行基線のグリッドを別の設定にする。フォントサイズを維持してグリッドの間隔へ文字送りを広げる方式と、自然な文字送りを維持してブロック境界だけを揃える方式は、見た目と1行の収容文字数が変わる。ユーザーの GridLayout の意図に合わせて選ぶ必要がある。参照 PDF の文字間隔から自動的に決めない。

### 等号は文字列の中央揃えではなく、意味を持つ列の共通アンカー

`08_線路.pdf` p2 の断面積・断面二次モーメントは以下の座標を持つ。

| 対象 | 基線 y | 第1等号 x | 結果前等号 x | 数値右端 x | 単位開始 x |
|---|---:|---:|---:|---:|---:|
| 断面積 `A = 4.50 × 2.70 = 12.150 m²` | 181.918 | 214.08 | 402.24 | 465.56 | 474.24 |
| 断面二次モーメント `I = … = 7.38113 m⁴` | 196.798 | 214.08 | 402.24 | 465.56 | 474.24 |

基線差は14.88 pt。数値は桁数が違っても右端が揃い、等号と単位は独立した列に載る。p2 の重心位置・弾性係数も第1等号 x=214.08 ptを共有する。

`07_荷重計算.pdf` p1 の4本の反力式は、第1等号 x=154.56 pt、結果前等号 x=391.32 ptを共有する。基線 y=568.798、597.598、635.038、672.478 pt。2本目の代入式は途中で次行に折り返すが、結果前の等号列は維持される。等号の左右を別々に測り、式の継続行と結果列を管理する必要がある。

`08_線路.pdf` p3 の結果前の全角等号は x=435.48 ptを繰り返し使う一方、左側の等号はx=165.00 / 176.76 / 200.28 ptと用途に応じて異なる。文書全体のすべての等号を1列に強制するという参照ではない。**ブロックまたは名前付きグループごとのアンカー共有**が合う。

半角 `=` と全角 `＝` が混在する。アンカーを字形の左端・中心・数式軸のどれに合わせるかを定義しないと、同じ座標を指定しても見た目がずれる。新 API は関係演算子を文字列から推測せず、`relation` のような構造を持たせるのがよい。

## ページ・余白・改ページ

多くのサンプルは右上にページ番号を持つ。`07` p1 の `7 - 1` と `08` p2 の `8 - 2` は x=523.32、基線 y=52.318 pt、11.5 pt。`12` p1 の `244` は x=534.84、y=52.318 pt。`14` p1 の `326` は x=543.48、y=43.678 pt。番号の形式と位置は完全に統一されていない。ページ番号テンプレートと予約領域は設定可能にする。

サンプルにはページ末尾の大きな余白を持つページもある。`08` p2 は上半分で小節が終わる。これだけから、自動改ページ・強制改ページ・意図した章境界のどれかは判別できない。

**提案:** `keep_with_next`（見出しと次の内容）、`keep_together`（数式導出等）、明示改ページ、表の行単位分割を別々の規則として定義する。1ページを超える分割禁止ブロックは、無限に次ページへ送ることなく、測定情報とブロックIDを持つエラーにする。原稿と見本のページ数一致を既定の合格条件にしない。

## 見本をそのまま正解画像にしない理由

- A4 グリッドとは異なる文字送り・行間が確認される。新ライブラリで書式統一する以上、すべての既存座標の一致を要求すると目的と衝突する。
- `14` p1 とp11 の右端に青い矩形と影があり、ページ端で切れている。由来は確認していない。これを共通帳票の標準装飾として再現しない。
- `14` のファイル名と本文見出し番号（§11）が一致しない。番号をテスト期待値として機械的に採用しない。
- 段分数・図・表の詳細などは、抽出テキストの並びが見た目の読み順と一致しない場合がある。文字列抽出のみで目視確認を置き換えない。
- PDF Producer、フォントの埋め込み、アンチエイリアスの違いによりバイト列や画素の完全一致は期待できない。

## テストと fixture の新設案

参照原本は移動・書き換えをせず、`tests/output` をそのまま保持する。生成物は別ディレクトリに出す。

1. `tests/fixtures/layout_cases/` に手書きの小さな部品データを用意する。例: `mixed_japanese_latin`、`two_anchor_equations`、`wrapped_substitution`、`fraction_and_scripts`、`unit_column`、`page_boundary_table`。参照の工学計算を再実装せず、表示用文字・数値を使用する。
2. `tests/fixtures/reference_manifest.json` に今回の原本ハッシュ・代表ページと目的を記録する。これを新しい生成 PDF の期待ハッシュに転用しない。
3. `tests/unit/test_grid.py` にグリッド座標・用紙座標変換・整数行の占有・端数処理を置く。フォントサイズと送りを混同しないこと、文字ボックスが枠を超える場合を検証する。
4. `tests/unit/test_equations.py` にグループ内の等号アンカー一致、式/結果/単位列の非重複、上下付き・分数の高さを置く。半角/全角等号・日本語とASCIIの混在を含める。
5. `tests/unit/test_pagination.py` にページ下端ちょうど/1行不足、見出し孤立、分割禁止の超過、繰り返し表見出しを置く。
6. `tests/integration/test_pdf_layout.py` で PDF を独立に抽出し、ページ寸法・文字の存在・アンカー座標・本文枠の内包を確認する。例えば等号位置の許容差0.1 ptは新たな提案値であり、参照から得た要求ではない。
7. `tests/visual/` に固定フォントと固定描画環境で生成した代表 fixture の承認済み画像を置く。初回は `07` p1、`08` p2、`13` p54 の構成を参考にした小さなページを目視承認し、既存251ページの丸ごと再現を先に目標にしない。
8. グリッド、文字枠、基線、等号アンカーを重ねるデバッグ描画と、配置結果を座標JSONで確認する仕組みを用意する。通常の出力はグリッドを表示しない設定を持たせる。

製品コードの分割候補は `src/gridlayoutpdf/geometry.py`、`grid.py`、`text.py`、`equations.py`、`blocks.py`、`pagination.py`、`rendering/`。最終的なモジュール境界は主計画で決定する。

## 実装前に確定が必要な点

- A4 の1セルに全角1文字・半角2文字を置くのか、開始位置だけをグリッドへ合わせるのか。基準フォントサイズ維持との関係。
- 文字基線のセル内位置、上下付きや分数などの内部組版をグリッド制約からどこまで除外するか。
- 等号アンカーを固定列で指定するか、グループ内の左辺最大幅から計算するか。複数の等号・結果列の扱い。
- 幅不足時の改行・エラーの規則。フォントサイズ維持が要件なら、無言の縮小はしない。
- 複雑な数式は構造 API で扱うか、外部の数式組版を部品として埋め込むか。式内部のアンカーを保持できるかを実験する。
- A3ページや外部PDFの挿入を初期範囲に含めるか。参照にはあるが、初期要件としての承認は別に必要。
