### Purpose

文章・数式・表・図を Python の部品として組み立て、共通の配置グリッド、文字書式、改ページ規則で PDF 計算書を出力する。特に、文字サイズを保ったグリッド調整と、計算式の等号・結果・単位の列揃えをライブラリの中心機能にする。

### Scope

以下では、確認済み要件、資料の実測、採用を提案する設計、変更対象を分けて記す。

- 1マスは部品の配置単位であり、全角1文字の枠ではない。文字サイズ・字形の縦横比を維持する。
- 上から自動配置し、必要な箇所だけ位置指定する。代表構成の出力によって表現能力を確認する。

- A4縦を標準とし、A3・横向き・同一PDF内の混在を初期版に含める。

#### 技術構成の提案

```text
利用側の計算結果・表示原稿
  → 文書部品ツリー（文章 / 数式 / 表 / 図）
  → 計測（文字幅・高さ・基線・分割候補）
  → 配置（グリッド・アンカー・折り返し・改ページ）
  → 確定したページと描画命令
  → ReportLab Canvas → PDF
                 └→ 配置JSON・グリッド付き検査出力
```

独自開発の中心は「計測・配置・改ページ」。PDFファイルの低水準生成には ReportLab Canvas を第一候補とする。Canvasは座標描画・ページ寸法変更を提供し、TrueType登録機構もあるため、この境界で使う案が合う。ただし日本語書体と数式記号の実用性はStep 2で実証する。[ReportLab graphics](https://docs.reportlab.com/reportlab/userguide/ch2_graphics/)、[fonts](https://docs.reportlab.com/reportlab/userguide/ch3_fonts/)。

Platypusのフローを中心に独自グリッドを後付けする方式は採らず、必要な制御を自作する。描画バックエンドは1実装と狭い契約に留め、複数バックエンド用プラグイン基盤は先に作らない。

- 実装言語案: Python 3.12以上。初期検証環境はWindows、最低対応版と作業環境のPython 3.13で確認する。OS固有のフォント探索を中核から分け、他OSの正式対応は別途検証する。
- 実行依存案: `reportlab`。必要なフォント解析依存はStep 2の結果で最小限に追加する。
- 開発依存案: `pytest`、PDFの独立抽出・画像化用 `PyMuPDF`。開発用抽出器を製品実行依存にはしない。
- バージョンはStep 1で解決・固定し、`uv.lock` を作る。採用する書体ファイル・face番号・ハッシュ・利用条件も固定する。MS明朝等が全環境にあると仮定せず、再配布しない。

#### 計測・配置の契約

1. **座標:** 中核は左上原点・pt。列・行は0始まりの整数境界。`x(c)=x0+c*dx`、`y(r)=y0+r*dy`で求め、加算の丸めを蓄積しない。PDFの左下原点への変換は描画境界で一度だけ行う。
2. **用紙プロファイル:** `A4_PORTRAIT_REFERENCE` と `A3_LANDSCAPE_REFERENCE` は実測寸法・行列数を保持する。初期既定は前者。厳密なISO寸法とは名前で区別する。A4横・A3縦は横縦ピッチを維持して再配置する生成プロファイルとし、原点・最小右下余白から整数行列数を切り捨て計算、余りは右下余白へ加える。基準の最小右下余白は罫線中心からA4の61.72/59.842 ptを使う案とし、参照PDFで実測した向きとは区別する。
3. **本文と装飾領域:** 本文の初期枠は参照グリッド30×47マス全体。ヘッダー・フッターはその外側の余白内に別枠を持ち、紙外や本文への侵入をエラーにする。カスタム設定では本文の使用行範囲を狭めて予約できる。罫線幅を含む描画外接矩形と配置境界は別に管理する。
4. **文字:** フォントの実測送りと、グリッド上の部品幅を分ける。本文10 ptを試作値とし、開始位置は列境界＋明示padding、基線は行境界＋styleのbaseline offsetに揃える。offsetは使用書体のascent/descentと字形で検証して固定する。基線を無条件にマスの中央へ置かない。
5. **字送り:** 既定は自然な送り。必要なラベル等には指定グリッド幅への均等な字間追加を提供する。拡大するのは字間のみで、字形は伸縮しない。追加量の上限案は1間隔0.05em、負の字間調整は禁止。上限を超えるなら文章は次の有効候補で折り返し、分割禁止ラベルは幅不足エラー。通常段落の最終行は均等割付しない。1マス1文字・半マス1文字への自動変換はしない。
6. **数式内部:** 分数・根号・添字・括弧内は連続pt座標で組む。数式軸と基線、上下の必要高を返し、外側の占有高さをグリッドの整数行へ切り上げる。添字の小さな文字サイズは明示した数式styleであり、幅超過時の自動縮小とは分ける。数式の文字を一つずつマスへ吸着させない。
7. **部品契約:** `measure(context, available_width)` が幅・ascent/descent・必要高・有効な分割候補を返す。配置処理が確定位置を持つ不変の結果を作り、描画処理はその結果だけを使う。計測中にCanvasを操作したり、再計測で部品が変化したりしない。
8. **書体:** 計測と描画は同じfont face・サイズ・glyph advanceを使う。必要な字形の存在を事前確認し、欠字はブロックID・文字を含むエラー。fallbackを設定する場合は計測前に書体を解決する。描画時だけ代替書体へ変えない。日本語、ASCII、ギリシャ文字、数学記号、結合文字の代表例を検証し、複雑な多言語組版・縦書きを初期版の保証範囲に含めない。

#### 数式とアンカーの契約

- `EquationGroup` 単位で第1等号、第2等号、結果右端、単位開始位置を共有する。文書全体の全等号を1列に固定しない。
- 関係演算子は構造として渡す。アンカーは関係記号の**送り枠の水平中心**を基準とし、通常は同じ書体・同じ `=` を使う。全角 `＝` を明示する場合も枠中心を合わせる。上下は数式軸を共有する。
- 日本語ラベルは専用のラベル枠内で折り返し可能とし、数式の左辺・数値結果・単位は初期版では分割禁止にする。長いラベルの高さも数式行の占有高へ含める。表示する数値は呼び出し側が書式化して渡し、ライブラリが勝手に丸めない。
- アンカーは列番号で明示指定できる。自動の場合はグループ内の列ごとの必要幅と間隔を測り、右方向の最寄りグリッド境界へ切り上げる。自動計算に第2等号・結果・単位の予約幅も含め、式の幅を残りから決める。明示アンカーが重なる場合はエラー。
- 一般式・代入式は `Row` の構造から折り返し候補を生成する。優先順位は強制改行、明示優先位置、最上位の関係演算子、加減算、明示許可した乗算等。候補間を貪欲に詰め、収まる最も後ろの候補で折り返す。同順位の規則は決定的にする。分数・根号・添字・括弧で束ねた部分は初期版では分割しない。
- 継続行は右辺開始位置へ揃え、折り返した演算子を継続行頭に表示する。結果が同じ行に収まらない場合は専用の最終行へ送り、結果前等号・結果右端・単位のアンカーを保つ。見かけだけでなく、入力された項・演算子の順序と個数が保持されることを検証する。
- 同じ幅で改ページしたグループはアンカーを維持する。用紙プロファイルが変わる場合は新しいグループとして再計測する。明示した用紙切替をまたいでアンカーを暗黙共有しない。
- 分割できない部分が領域より広い場合は、必要幅・使用可能幅・部品パスを示す `LayoutOverflowError`。暗黙の縮小、紙サイズ変更、切り落としは行わない。

#### 改ページと位置指定の契約

- 見出しは次の本文1行以上と一緒に送る。段落は有効な行境界で分割し、初期既定は先頭・末尾に各2行を残す。短い段落では存在しない行数を要求しない。
- `KeepTogether` は分割禁止。空ページにも収まらなければエラー。数式グループの通常動作は「1ページに入るならまとめ、入らなければ式の行境界で分ける」。各数式の分数等の内部は分割しない。
- 表は行境界で分割し、指定した全ヘッダー行を再掲する。rowspanが接続する一群の行は同一ページに置く。ヘッダー＋最小行群が空ページに入らなければエラー。結合セルを黙って切断しない。横幅超過時も自動縮小せず、呼び出し側がA3等のセクションを指定する。
- `At(row, col, col_span, block)` は現在ページのフローカーソル以降へ置き、占有する縦帯の末尾までカーソルを進める。過去の行への配置、本文枠外、既存部品との意図しない重複はエラー。明示位置の部品を勝手に次ページへ移さない。横並びは `Columns` 内で宣言し、高さは子の最大値から決める。
- 図の内部では、枠内のベクトル要素・ラベルの重ね合わせを許す。画像は指定枠に縦横比を保って収める。任意の図の周囲へ本文を回り込ませる機能は初期版に含めない。
- `PageSection(profile=...)` は新ページで開始。A4→A3→A4も明示する。空の先頭・末尾ページや、連続する改ページによる意図しない空ページを生成しない。
- ページ番号は固定予約枠に後描画する。総ページ数を必要とする書式でも本文の再フローを起こさず、予約枠を超えた場合はエラーにする。
- ページ送りは毎回「入力を消費する／有限の分割をする／エラー」のいずれかを必須とし、配置不能な部品を無限に次ページへ送らない。
- 検証・全ページの配置を完了してから一時PDFに描画し、成功後に出力先へ置換する。失敗時に既存の完成PDFを壊さず、エラーを成功として隠さない。

### Risks & Considerations

- **見本の表現をすべて再現できるとは未検証:** 14ページの調査から必要な部品を抽出した段階。Step 2の日本語・複雑な数式とStep 6の表を必須ゲートにする。既存251ページの全文移植はこの計画に含めない。
- **文字送りとグリッドの混同:** 全角送り10.08 ptとグリッド横16.08 ptは異なる。計測値と配置単位を別型・別設定にし、字間調整の前後で字形の重なりを検出する。
- **フォント依存:** 同じフォント名でも実ファイルが異なると幅が変わる。ファイルとfaceのハッシュを固定する。数式用の別書体は明示したfallbackとして事前計測する。互換性と書体の供給が確立するまで大量のgolden画像を作らない。
- **数式エンジンの範囲拡大:** 初期版は参照に存在する組み方を対象とする。TeX全体、任意の行列・大型演算子組版・数式解析まで一度に引き受けない。必要な追加表現は例と検証を付けて増やす。
- **自動アンカーと折り返しの循環:** 先に左辺・関係列・結果・単位の予約を決め、残り幅で右辺を分割する一方向の処理にする。ページ位置に合わせてアンカーを繰り返し変更しない。
- **表とページ分割の複雑さ:** rowspanのつながりを先に分割禁止の行群へ解決し、通常の行分割に渡す。巨大な1セルを勝手に分ける機能は初期版に入れない。
- **回帰検証の循環:** 配置器が出した値をそのまま期待値にしない。手計算座標、独立したPDF抽出、目視を併用する。PDFバイト列一致を要求しない。
- **利用側への抽象化漏れ:** 多数の `drawString(x, y, ...)` を別クラスに移すだけでは目的を満たさない。利用例が文章・式・表とグリッド列だけで組めることをStep 7で検証する。
